# company_3d — 三维场景与素材库

团队 3D 工作的统一目录。**约定优先于个人习惯**：文件放错位置会直接导致流程断裂，
所以位置、命名、状态三项必须遵守。

---

## 1. 目录结构

```
company_3d/
├── 00_pipeline/        # 制作流程说明、自动化脚本、导出预设、环境依赖
├── 01_assets/          # 素材库（源文件级）：模型、贴图、材质
│   ├── models/
│   ├── textures/
│   └── materials/
├── 02_scenes/          # 场景工程文件（Blender/C4D/UE 等工程本体）
│   ├── wip/            # 制作中，随时可能坏，不要被下游引用
│   └── published/      # 已定稿，可被渲染/下游引用
├── 03_scripts/         # 一次性脚本、批处理、工具（可执行代码）
├── 04_library/         # 可复用元件：HDRI、预设、节点组、树/人群等
├── 05_renders/         # 渲染输出，按阶段分开
│   ├── preview/        # 快速预览、草稿、给同事看的版本
│   └── final/          # 交付级成图/成片
└── 06_docs/            # 文档：需求、评审记录、镜头表、交付清单
```

### 每个目录放什么 / 不放什么

| 目录 | 放 | 不放 |
|---|---|---|
| `00_pipeline/` | 流程文档、导出预设、`requirements.txt`、`setup.sh` | 工程文件、渲染图 |
| `01_assets/` | 单个可复用元件的源文件（.blend/.fbx/.png/.exr） | 完整场景、成片 |
| `02_scenes/` | 场景工程本体 + 其专属贴图子目录 | 团队公共贴图（放 01） |
| `03_scripts/` | 可执行的 .py/.sh/.js 工具与批处理 | 一次性临时脚本（用完删） |
| `04_library/` | 跨项目复用的 HDRI、节点组、预设、第三方库 | 某场景专用内容 |
| `05_renders/` | 图片序列、成图、成片 | 未渲染的工程文件 |
| `06_docs/` | 需求单、评审意见、镜头表、交付清单 | 代码、二进制资产 |

**判断规则**：如果是"能被别人的场景引用"的单个东西 → `01_assets/`；
如果是"一个完整的场景工程" → `02_scenes/`；如果是"渲染出来的结果" → `05_renders/`。

## 2. 命名规范

格式：`<类别前缀>_<主体>_<变体>_v<主>.<次><状态>`

| 字段 | 规则 | 示例 |
|---|---|---|
| 类别前缀 | 小写，见下表 | `mdl` `tex` `mat` `scn` `rnd` |
| 主体 | 小写英文 + 连字符，不用空格/中文 | `office-tower` `hero-chair` |
| 变体 | 可选，小写 | `low` `high` `lod0` |
| 版本 | `v` + 主版本 `.` 次版本 | `v01.03` |
| 状态 | 可选后缀 | `_wip` `_rvw` `_apr` `_fin` |

全小写、下划线分隔字段、连字符分隔单词。**禁止**：空格、中文、`final_final`、
`新建文件夹`、日期当版本号（`20241016` 这类不是版本）。

### 前缀速查

- `mdl_` 模型　`tex_` 贴图　`mat_` 材质　`scn_` 场景　`rnd_` 渲染
- `prs_` 预设　`lib_` 库资源　`ref_` 参考图　`doc_` 文档　`scr_` 脚本

### 正确 / 错误对照

```
✅ scn_office-tower_day_v01.02.blend
✅ mdl_hero-chair_low_v03.00_apr.fbx
✅ tex_metal-panel_rough_v02.01.exr
✅ rnd_office-tower_hero_v01.04.png

❌ 办公大楼-最终版.blend
❌ Scene Final Final.blend
❌ chair_new_new2.fbx
❌ texture(1).png
❌ render 2024-10-16 final.png
```

## 3. 版本规则

- `v<主>.<次>` 两位补零：`v01.00`，不是 `v1.0`。
- **次版本 +1**：改了材质、灯光、相机、小修模型 → `v01.01`
- **主版本 +1**：结构改动、构图重做、模型重做 → `v02.00`
- 旧版本**不删除，不覆盖**，留在原目录；用 `_apr` / `_fin` 标记定稿版本。
- `published/` 里同名文件只能有一个"当前版本"，靠版本号大小判断，不要靠修改时间。

---

## 4. 状态标记

| 后缀 | 含义 | 谁能动 |
|---|---|---|
| `_wip` | 制作中 | 作者本人 |
| `_rvw` | 待评审 | 评审人只读 |
| `_apr` | 已通过 | **只读，禁止修改** |
| `_fin` | 已交付 | **只读，禁止修改** |

`published/` 下只允许存在 `_apr` 和 `_fin` 的文件。
要改已定稿的东西 → 复制回 `wip/`，升主版本号再改。

---

## 5. 三条硬性红线

1. **不动别人的文件。** 要改，先复制到自己名下并升版本号。
2. **不覆盖已定稿文件。** `_apr` / `_fin` 视为只读。
3. **场景所需的贴图/模型必须带进场景目录**或明确记录依赖来源，
   不允许引用桌面上的临时文件。

---

## 6. 日常工作流

```
04_library / 01_assets         参考与素材
        ↓
02_scenes/wip/                 制作（_wip）
        ↓ 自检通过
02_scenes/wip/                 提交评审（_rvw）
        ↓ 评审通过
02_scenes/published/           定稿（_apr）
        ↓
05_renders/preview/            快速预览 → 确认构图
05_renders/final/              最终渲染 → 交付（_fin）
```

渲染输出命名必须能反查场景：
`rnd_<场景主体>_<镜头>_v<版本>.<扩展名>`，例如
`rnd_office-tower_hero_v01.04.png` ↔ `scn_office-tower_day_v01.04.blend`。

---

## 7. 新场景起步

```bash
cp -r 00_pipeline/templates/scene-template 02_scenes/wip/scn_<名字>_<日期>
```

（模板目录待建；若不存在，直接手建同名目录并把共享贴图放进去。）
